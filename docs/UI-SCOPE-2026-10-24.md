### 3. The decided fixes (they change behaviour)

**3a. One counting rule (decision 1)**
- **Processed:** every line the channel answers counts as processed. That covers every table row, every lane verb, and an allowlisted cvar. The table's `counted` column goes.
- **Rejected:** these get one rejection reply, `result=rejected verb="…" detail=…`.
  - A word that is not a verb: `detail=not_a_channel_verb_and_not_allowlisted`, as now.
  - An unknown verb under a lane's prefix (`carry.bogus`, `grenade.bogus`, `mem.bogus`, `arms.bogus`, `wrist.bogus`): the same reply. Each lane's dispatcher returns false for a verb it doesn't know, instead of replying `result=1` itself.
  - A verb short of its arguments: `detail=missing_arguments`. These are `use.find`, `hud.setvar`, `hud.fit`, `xr.runtime`, `console` and `move.bind`. `hud.call` joins them with a minimum of 3, in place of its own `need_function_and_value` reply.
- **The `arm.` prefix becomes 12 rows**, `arm.mode` to `arm.knee`: the settings TUNING-COMMANDS.md lists.
  - `arm.bogus` is then rejected like any other word.
  - `arm.torso` and `arm.length` are tagged `player`, because the doc marks them **Menu**.
  - The lookup becomes: exact row, then the lanes, then the allowlist, then rejection.
  - The doc check stops exempting `arm.`, so the rows and the doc must list the same settings.

**3b. One parsing rule (decision 2)**

- **The same rule covers `mem.*` and `arms.hide`.** The decision didn't list them, but `mem.watch`'s slot and captures, `mem.stack`'s index and `arms.hide`'s index also used `atoi`. Each keeps its fallback, so:

## Decisions for you
Decisions 1 to 4: **yes** (10-24); for 2, as recommended. Decision 5: **stays out**. Decision 6: **yes, as recommended** (10-24).

1. **One counting rule for the channel?** Every verb a dispatcher answers counts as processed. An unknown verb under a lane's prefix (`carry.bogus`) counts as rejected. A verb short of its arguments replies `detail=missing_arguments` instead of "not a channel verb". A short `hud.call` counts as rejected. I'd recommend yes: the counts are only read in reports, and today's rule follows the C1061 split, not anything meant.
2. **One parsing rule** (your A9 decision: a malformed value falls back to the default)?
   - Integers become decimal only: today `0310` is octal.
   - `wrist.*` stops using `atoi`, and `carry.*`/`grenade.*` stop accepting `12abc`.
   - The six verbs that refuse a malformed value (`near.fov`, `ik.align`, `dbg.draw`, `aim.shot`, `near.fx`, `markers.depth`) fall back like the rest.

   I'd recommend yes for the first two. For the six, I'd recommend keeping the refusal: each is a switch where a typo's fallback would turn something on.
3. **The fallbacks that disagree with the Spec?**
   - `hud.layer abc` falls back to 0 (the Spec says 1).
   - `move.headrelative abc` falls back to 2, which the lane refuses.
   - `move.snap abc` falls back to the current value.

   I'd recommend the Spec's defaults: 1 and 1, keeping `move.snap` as it is.
4. **The replies:**
   - add `result=0` to the six that lack it (`haptics`, `aim.scene`, `vr.options`, `contact`, `surface`, `swing`);
   - `near.fov` stops switching `near.follow` off when it refuses;
   - a multi-value setter given too few values replies `result=87` instead of 0;
   - the `report` log line holds only the report.

   I'd recommend all four. Nothing reads these replies but people and the tuning script, which only prints them.
5. **The lasers: split them out of the debug overlay now?** A real split moves the eye-image renderer into its own file, shared by the lasers and the overlay, and gives the lasers their own switch and producers. I'd recommend leaving it for the instrumentation gate, which is the first thing that needs it. Until then a split moves code without changing what anything can do.
6. **Values with no default to fall back to: refuse them?** (Found while scoping phase 3.)
   - **`arm.*`:** today a malformed value becomes 0 (`ArmSetting`), and most settings accept 0:
     - `arm.torso abc 600` sets the body turn deadzone to 0;
     - `arm.mode abc` picks the native arm;
     - `arm.lift abc` turns the torso lift off.

     The channel has no default for each setting's values, and each setting takes several.
   - **`hud.setvar`, `hud.call` and `hud.probe`** read their numbers with `atof`, so `hud.setvar <path> abc` writes 0 into the HUD.

   I'd recommend refusing the line with `result=87`, as `ui.offset` does. The alternative, a default for each arm setting, would put the 12 settings' defaults in the channel a second time.
