- `InventorySwapchain`, `InventorySwapchainApi`, `kInventoryMinWidth/Height` and `InventoryTextureCompatible` serve 11 layers, not just the inventory.

### Tests today
- The `inventory_swapchain` test drives the swapchain wrapper against a simulated runtime with real WARP textures.
- `ui_panel`, `xr_frame_contract`, `xr_hold` and `stereo_frame` cover the pure parts.
- **XrSessionHost itself has no offline test.** `command_channel` and `vr_options_wiring` link it but never start a session.

## Goal and non-goals

**Goals:**
- **Each repeated layer pattern written once**, with the shared pieces taking the swapchain API struct, so the simulated runtime in the swapchain test can test them.
- **XrSessionHost split along the seams above**, with `ServiceXrFrame` reduced to an orchestrator of about 300 lines.
- **The wrapper named for what it is.**

Everything is **behaviour-identical**: the same XR and D3D11 calls in the same order, and the same log lines, verbs, replies, report keys and export names. The one exception is listed under phase 1.

**Not in this batch:**
- **HudLayer's own repeats (B10)** go in the UI batch. Only its three renderer-device reads change here, because they become one accessor.
- **The GDI text painting copies:** the guide card, the slot card and the debug overlay's atlas each build a GDI DIB section. They are UI code with different post-processing, so they go to the UI batch.
- **Anything that changes what is submitted**, such as the runtime's recommended resolution or the IPD source (S7's latent desync, T3).

**Phase 3 turns ServiceXrFrame's overlay sections into functions.** These are the HUD through the fade, 2422-2791. They take a `FrameView`: the located views, the head, the reference, the display time, and `rendered` / `haveViews` / `panelActive` / `optionsActive`. Each returns its layer and whether it is shown.
- The calls stay in today's order, because some sections feed the next: the HUD panel's width sizes the world reticle, and the wrist decision reads this frame's tracking.
- This is the one part that is not a move, so it gets its own diff review against the table above.

**Kept through both phases:**
- **The top of `ServiceXrFrame`** still takes the contract, the both-eyes hold and every capture before its first return.
- **Every file logs with the `preyvr_xr_session ` prefix**, through the shared `Log`.
- **The lock discipline is unchanged.** The render thread takes `gMutex` through `LockForRenderThread`, control calls wait at most 250 ms, and the hold thread only tries the lock.

**Where this differs from the plan:**
- **One package,** your decision 3.
- **`ServiceXrFrame` is 567 lines, not about 300.** The overlays came out as planned; what is left is the frame's own sequence (wait and locate, the world image, the menu panel, compose and end), whose sections share a dozen locals. Splitting those is a later step if wanted.
- **The HUD section now calls `UploadPanelCapture`.** Its own copy was the same code with the same log lines, as the audit noted.
- **The private namespace is `xrsession`, not `xr`:** `preyvr::xr` already exists (FrustumCoverage), and `preyvr::dll::xr` would hide it inside the DLL.
- **`AcquiredImage` has an `Acquire` step:** MSVC would not construct it in place through a conditional.
- **`kMaxLayerExtent` is used at 2 of the 4 sites** (LayerSwapchain, HudLayer). UiPointer and NativeWristTexture are built into tests without the OpenXR headers, and NativeWristTests is receipt-pinned. Their 8192 stays written out.
- **FrameCaptureWin32's two `GetBuffer` calls stay.** Only its renderer reads changed: its HUD-only path puts an AddRef'd HUD texture into the same variable.

**Behaviour differences, all on failure paths:**
- **The format checks:** as scoped, the guide card's and the laser's pickers gain the 0-or-256-or-more count check, and the guide's also stops on a failed format enumeration.
- **The guide card's image enumeration:** `CreateStaticLayer` checks both image-enumeration calls, where the guide ignored the first.
- **COM references** are released at the end of their scope rather than at the line that released them. That does nothing to the device.
